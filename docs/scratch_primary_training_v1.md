# 随机初始化折叠核心：正式主训练方案草稿

状态：2026-09-27，按用户“先起草主训练计划”的要求编写。本文是待落实的实施方案；尚未新增主训练作业，不把候选预算视为已完成训练。沿用 [总体研究路线](scratch_model_plan_v1.md)，将工作重点推进到可恢复的全量训练工程。

## 1. 本轮决定与现有证据

主线采用冻结 ESMC-600M、随机初始化折叠核心、实验结构 GT 监督、MSA-off、c1/s1/K1。先训练一个可比较的基础版本，再根据完整训练曲线决定模型改造。

TRAIN4 两臂及独立验收已完成。smooth-lDDT 在全部10个共同非零检查点提高平均全原子 lDDT；同500曝光时均值0.92660→0.93887，最低蛋白/噪声分数却0.91475→0.91111。两组分别在500/550曝光联合通过。可将 smooth 项作为主线候选，不能据此宣称更快联合达标或更强泛化。见 [结果复核](../reports/esmc_scratch_overfit_v1_20260927/review.md)。

三项直接影响实施的事实：

1. 全量选择清单为29,769个TRAIN精确序列组，长度20–1024，共8,830,652残基；历史DEV1600全部排除，旧8192结构代表保留。
2. 全部29,769已有旧final-layer ESMC缓存，但只有8192 TRAIN＋128 DEV结构包确认验收通过。还需准备21,577个TRAIN结构包，其中5373条≤256残基、16,204条>256残基。
3. 新12/24/36层特征提取已完成，547分片的清单覆盖等元数据检查通过；全量张量及跨设备数值兼容检查尚未完成。它是MLC候选输入，本版主线无需等待MLC，也不会把新缓存未经核对地替换旧final特征。

依据：X570 `reports/esmc_29769_extraction_2026-09-27/completion/status.json`、`selection/selection_report.json`；HPC3 `/data/user/shuang886/Folding/esmc_expansion_data_v1_20260927/acceptance.json`。数据状态需在运行锁定时再次确认。

## 2. 模型与训练配方

| 项目 | 主线v1候选 |
| --- | --- |
| 序列表征 | 冻结ESMC-600M final-layer，1152维，绑定既有缓存版本与逐残基顺序 |
| 折叠权重 | 投影与全部折叠核心随机初始化；主训练seed101；不加载TRAIN4/32拟合权重 |
| 拓扑 | 已验收的16层Pairformer、8层结构Transformer，raw XYZ全重原子输出 |
| 部署 | 一次trunk cycle、一次structure evaluation、一个样本；MSA/template关闭 |
| 监督 | `A + 0.1F + R + 10D + 10 L_smooth`；全部来自观测实验GT |
| 优化器 | AdamW，全部可训练参数统一峰值lr=1e-4，wd=1e-4，clip=10 |
| LR草案 | 1000次完整optimizer更新warmup，随后按预定50epoch预算cosine降到1e-5 |
| 精度 | BF16 trunk、FP32结构与距离损失、TF32关闭；对齐保持已验证的FP64计算 |
| 正则化 | 首版明确保留dropout=0；不静默恢复上游默认dropout |
| 暂不参与优化 | confidence/distogram head冻结且不执行；后续独立实现置信度训练与校准 |

A/F/R/D 保持已验收归一化。smooth项使用观测重原子、GT距离<15Å、跨残基原子对、逐原子邻域平均；阈值0.5/1/2/4Å，sigmoid温度0.1Å，权重固定10。真实评分仍使用硬阈值lDDT。

warmup是批量变化后的优化稳定措施，不是解决质量差距的主张。当前训练噪声/一步输出路径保持原协议；本版不把普通多噪声训练、MeanFlow、MLC、distogram监督和增加深度同时加入。新主线沿用既有架构模块，但不复用折叠权重；这不是架构独创性结论。

## 3. 开跑前只保留必要检查，并行推进

### A. 一次TRAIN32学习检查

将现有TRAIN4入口和独立验收实际扩展为TRAIN32，不能只在命令行改数字。使用同一原TRAIN32、随机seed101、smooth权重10和已验收小集优化器；每50曝光评估，每蛋白最多1000曝光，优化窗口最多10小时、Slurm硬上限12小时。通过后停止，其checkpoint不进入正式主训练。

两种评估噪声分别要求：每条蛋白全原子lDDT≥0.90；历史TRAIN32几何条件为 pooled atom RMSD≤1Å、至少29/32的atom RMSD≤2Å、pooled Cα距离RMSE≤1Å、三类同残基键RMSE≤0.15Å、C–N≤0.30Å、手性一致率≥95%。逐蛋白化学误差另外完整报告，不能把pooled通过说成每条均通过。

该检查只用于确认候选在更大记忆集上可学；不再自动重跑整套1/4/32架构网格。如果要声称smooth相对baseline的TRAIN32效率优势，再增加同协议baseline；旧历史baseline不冒充本轮严格配对对照。数值失败先定位实现；达到时间/曝光上限但未通过则记录失败类型，不直接开放全量长任务。

### B. 全量结构包准备与验收

与A并行，复用已验收8192 TRAIN和128 DEV，补齐其余21,577个TRAIN包。另为锁定后的DEV-primary补齐结构包并核对final特征覆盖；不能把已有DEV128的准备状态等同于更大开发集已就绪。使用冻结选择清单与实验构建体序列，不改成UniProt全长，不拼接观测片段，不用预测结构填补缺失标签。

对序列/残基/原子名字映射、GT坐标与掩码、化学参考输入、ESMC逐残基对齐、文件哈希做完整验收。GT只进入监督；参考化学坐标不能携带目标折叠。空监督类别和缺失观察必须明确计数及损失行为，不能静默跳过目标或制造标签。失败记录隔离；改变训练清单时必须新版本并重算曝光/预算。

长链保留全长20–1024，第一版不默认裁剪。若显存预检失败，先做等价内存优化；不能把跳过长链或裁剪后的数据继续称作全量全长训练。

### C. 长链、并行与恢复检查

从TRAIN按长度档20–128、129–256、257–512、513–768、769–1024选择固定代表，并包括最大原子数、最多邻域pair数及最长链。实测完整前向、反向、optimizer状态建立后的峰值显存与耗时。

现有训练核心使用`chunk_size=None`；现有smooth损失虽然用稀疏pair，仍一次保留所有pair的反传中间量。必要时实现经梯度等价验证的activation checkpointing/损失分块；仅在循环里累加分块loss不保证释放反传图。CPU输入缓存需有界，raw路径不应为每条长链额外缓存无用的GPU几何adapter。

再用固定TRAIN512中的代表执行最多200次更新的工程预检，验证DDP、累积、尾batch、中断恢复与吞吐。它不承担完整TRAIN512拟合实验，也不据短跑开发分数宣称收敛。预检权重丢弃，主训练重新从seed101开始。

## 4. 正式主训练的数据遍历和并行规则

默认HPC3 `acd_u`，4×H100，每卡microbatch=1，累积4次，完整global batch=16。该配置待长链预检确认。DiamondHill的8个GCD是已有授权的资源选项，需单独通过ROCm/分布式精度和吞吐检查后锁定；不把跨硬件结果直接当作严格质量对照。

每个epoch每个TRAIN序列组恰好出现一次；确定性打乱后在小池内按长度分组，再打乱组顺序。记录真实蛋白曝光、残基/原子token和长度分层覆盖。首版不按DEV错误重采样，不把精确序列去重称作同源家族去重。

29,769不能被16整除：每epoch有1860个完整batch＋一个9条尾batch，共1861次更新。不得`drop_last`，也不得把重复补齐的样本计入真实曝光。若DDP world size为W、当前更新真实蛋白数为N，每个真实样本loss乘W/N，经过DDP平均归约后得到全局逐蛋白均值。四卡满batch为1/4，尾batch为4/9。所有rank保持相同执行步数，空槽采用明确零权重padding并单独计数。

`no_sync`覆盖forward和backward；最终microbatch归约，累积完成后仅clip一次，再执行optimizer/scheduler更新。要求满batch、9条尾batch、不同长度与掩码情况下的损失/梯度与单进程参考在预声明数值容差内一致。

## 5. 预算、检查点和停止规则

建议完整研究预算上限为50个epoch：93,050次optimizer更新、1,488,450次真实蛋白曝光。50遍只是第一版训练预算，不是充分收敛保证。

分段检查点固定为epoch 1、5、10、20、35、50。首个主训练执行段以epoch5或24小时优化窗口先到者停止并保存；4卡对应最多96优化GPU小时，验收开销另列。工程预检确认真实吞吐后，先给出包含数据加载、评估与保存的小时数估计，才锁定各段Slurm资源上限。

后续采用相同50epoch LR轨迹和完整AdamW状态续训，不重启warmup。epoch20对应37,220更新、595,380次曝光；从20延到50不会重新定义原有学习率曲线。超过50epoch属于新预算阶段，需要依据已完成曲线另行记录，不能无限自动续训。

计时估算基于真实长度混合的稳态更新速度，不外推TRAIN4的短链速度。基本式为 `GPU小时 = 卡数 × 更新数 × 平均更新秒数 / 3600 + 评估/保存/验收开销`。在吞吐实测前不承诺具体完成日期。

数值非有限、输入合同不符、数据缺失、反传/NFE违反协议立即停止并保存诊断。墙时到期表示预算截断；恢复必须从明确的完整更新边界继续，不把中断解释为收敛。若连续两个正式检查点训练探针与开发指标均在预声明容差内停滞，则审查学习曲线与分项梯度，再决定继续或改变方法；不得仅因短跑scratch低于预训练就判定上限。

checkpoint至少包含model、optimizer、scheduler、epoch、下一batch游标、全局更新、各rank RNG、曝光计数和数据/代码/运行配置哈希。原子保存`last`，保留正式检查点。恢复检查须重现下一批、噪声、损失及后续权重；微批中途不保存可续训状态。

## 6. 评价、尾部和模型选择

继续保留DEV128作历史对照；它已多次用于开发，不能承担独立最终泛化结论。主训练前在原预留开发池中锁定一个更大的`DEV-primary`，优先覆盖1024条有效目标及各长度档，具体数量由元数据和标签可用性审计决定。它是模型选择集；不足1024时如实报告，不能从冻结test补齐或宣称足够测定1%尾部。

从TRAIN锁定512条按长度、结构质量及家族覆盖分层的探针，定期评估；正式检查点再评估全TRAIN或明确的更大预声明子集。不得以TRAIN32的分数代替全量训练拟合程度。轻量曲线按预声明更新间隔报告，完整DEV-primary在固定epoch检查点评估，额外成本计入资源预算。

评分沿用现有观测全重原子口径、15Å跨残基邻域和逐蛋白宏平均；单独报告均值、中位数、P1、worst-1%-mean、worst-5%-mean、低于0.70的蛋白比例、Cα-lDDT/TM及逐蛋白化学误差。P1与最低1%均值分别定义。两个推理噪声分别计算失败率/尾部，另保留逐蛋白两噪声平均的历史口径；禁止best-of-K。

额外审计训练—开发同源性，同时记录identity和双向覆盖率，避免把只覆盖较短序列的identity当成完整链近邻。长度和同源分层分别报告；没有合格比对不能直接标为新折叠。置信区间需考虑同源簇相关性。

始终报告固定预算终点`last`。另记录用于模型选择的`best_tail`：在既定化学验收范围内，优先较低的K=1失败率，其次较高的worst-5%均值，再比较总体均值；两噪声取较差统计，完全平局取更早检查点。不得只取总体均值最高的checkpoint并隐藏尾部退化；如果尚无化学合格候选，明确标记`best_tail`未通过，不默认推广。具体DEV集合、化学容差和停滞容差在第一步正式训练前写入运行lock。

最终目标仍是同口径全原子均值0.89–0.90、P1≥0.70，并满足完整化学与速度目标；这些是研究目标，不是本轮可保证的结果。候选固定后再做独立训练种子重复（至少3个，按资源计划分批），校准置信度并执行原冻结测试。开发集用于选模型，最终测试只用于确认。

## 7. 实施产物与放行顺序

计划新增独立的`src/fastglycan/scratch_primary.py`、`scripts/train_scratch_primary.py`、数据锁定/验收、DDP预检、checkpoint验收与报告入口；代码命名可在实施时调整。旧运行源码和已验收结果保持不可变。

现有`train_pretrained_esmc_gt.py`硬编码预训练初始化、4卡、2048/8192、原四项loss与4096更新；`gt_epoch_batches`拒绝尾batch；现有scratch入口只接受4条。因此正式实施包括新的初始化、loss接入、调度、累积/尾batch、恢复、长链输入缓存和分层报告，不能宣称已有训练器现成支持。

建议顺序：

1. 并行准备全部结构包、TRAIN32检查和新训练器；形成数据/源码验收报告。
2. 完成长链峰值、DDP数值归一化、200更新及恢复预检；锁定DEV-primary、吞吐估计和首段资源预算。
3. 重新随机初始化，启动全量final-only主训练首段；固定检查点汇报训练、开发、尾部与化学曲线。
4. 根据预声明条件继续同一运行到20/50epoch；确认候选后进行种子重复和最终验收。

若训练集本身持续偏低，优先检查监督、优化和表示容量；若训练集很高而开发低尾很差，优先检查数据覆盖、上下文与泛化。MLC、结构深度8→12、distogram、MeanFlow/一致性训练分别作为后续单变量候选。新方案可以沿用一个数据与评估框架，但不得把多项改变的收益归给某一项。
