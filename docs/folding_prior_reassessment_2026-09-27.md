# 基础折叠能力与下一项诊断：2026-09-27

## 当前结论的修正

32 条蛋白的容量门通过，只能证明小集可记忆。此前将状态概括为
“优化、容量已经解决，下一未知只有泛化”过于宽泛。完整 TRAIN2048
仍有明显结构误差，因此下一阶段必须同时解释训练集拟合效率和泛化。
这不是某个单独实现错误、ESMC 失效或一步部署不可行的证明。

已有 `reports/esmc_scaling_2026-09-19/raw_2048/report.json` 中，最佳
checkpoint 为 22528 次 batch=1 更新。两个固定噪声视图的结果约为：

| 相同观测原子与指标口径 | TRAIN2048 | DEV128 |
| --- | ---: | ---: |
| 全原子 lDDT（排除同残基原子对） | 0.5521 | 0.5375 |
| Cα-lDDT | 0.6274 | 0.6085 |
| TM-score | 0.7379 | 0.6967 |

训练集本身低分，且 Cα 局部距离也不准确，不能把主要差距只解释为侧链、
手性或泛化。DEV 与训练集同源性较高，小的 train–dev 差距不是独立泛化证据。
两个噪声视图不是两个独立训练 seed，也不是 best-of-K。

本轮 raw 延续的“8192”指新增更新数，**不是 8192 条训练蛋白**。
它仍使用同一 TRAIN2048；22528+8192=30720 次蛋白样本曝光。
新增8192点的 DEV 全原子 lDDT 约0.5848、Cα-lDDT约0.6610仍为 worker
分数，待独立验收。完整训练集的新结果也应在验收后报告，不能只外推32条探针。

## 已核对的训练差异

- `scripts/train_esmc_scaling.py` 用禁止 `torch.load` 的构造保护确保折叠核心
  随机初始化；冻结的预训练 ESMC 不等于预训练折叠核心。
- 当前 raw/geometry 延续均优化 A+0.1F+R+10D；distogram head 冻结且未调用，
  未计算 smooth-lDDT。配置字段存在不等于自定义训练循环执行了对应监督。
- `src/fastglycan/models/esmc_core.py` 训练也走 N_cycle=1、N_step=1、
  N_sample=1 的最终坐标监督。既有协议记录的噪声 schedule 为[2560,0]；
  改随机种子不等于覆盖多噪声尺度。
- 部署 c1/s1/K1 约束不要求所有训练过程也只有固定高噪声终点监督。
  但目前没有多噪声训练在本项目优于现配方的因果证据。
- 固定高噪声参数本身不能证明尺度爆炸；原生预条件化仍在。
  C–N监督、缓存对齐和梯度连通性已检查，不重复启动同类诊断。

原论文报告 Mini 用 batch64、200K iterations，Mini-ESM 再从 Mini 权重
继续训练100K iterations。仅前阶段约1280万样本曝光，是当前30720的约417倍；
这不是等 FLOPs、等蛋白数或等原子 token 比较，也不是建议照搬训练预算。
参见 [Protenix-Mini §4.1](https://arxiv.org/html/2507.11839v1)。

官方 loss 实现确有 distogram 和 smooth-lDDT 路径；这支持将其列为后续候选，
不能推出添加它们必然追回某个固定分数。
参见 [Protenix loss 源码](https://github.com/bytedance/Protenix/blob/main/protenix/model/loss.py)。
这里的网页 main 是查阅时版本；当前实验行为以冻结的本地源码为准。

DCFold 明确从 Protenix 初始化，并分别进行 diffusion 与 Pairformer 一致性
训练；它支持“一步部署可以使用更丰富训练”的方向，不支持随机核心用当前
小预算即可达到相同质量的结论。
参见 [DCFold §3.2、§4.1](https://arxiv.org/html/2605.17899v1)。

## 下一项只做一个诊断方向

优先回答：**保留成熟折叠核心后，ESMC 接口适配能保留多少 c1/s1 质量？**
这也是 `docs/protein_direction.md` 已要求但尚未完成的匹配初始化对照。
保留 scratch 结果作为参考；预训练诊断不改写为“从零训练成功”。

执行顺序：

1. 审计原版 Mini-ESM checkpoint 与当前核心的 keys、shape 和保留张量；
   不以宽松加载后没有报错作为兼容证据。CPU 作业654802已完成（33秒）：
   两边均1613个张量，无缺失或额外key；唯一shape差异是
   `input_embedder.linear_esm.weight`，原版449×2560，当前449×1152。
   其余1612个张量（134067007个元素）加载后逐项完全相等。
   这是张量兼容证据，尚无功能复现或质量保留结论；无训练或推理。
   原始报告：`reports/esmc_pretrained_compatibility_2026-09-27/report.json`。
2. 先用原生 ESM2 输入验证保留核心的功能复现，再检查现有配对 ESM2/ESMC
   缓存的残基顺序、层选择和数值分布。已发现640个既有 teacher sequence
   packets；尚未据此宣称其中 embedding 可直接复用。
3. 接口对齐后，锁定一个小规模适配协议，冻结其余核心先验证输入桥接；
   记录训练集误差与未用于桥接拟合的开发集质量。输入层形状兼容不能证明
   语义信息充分，桥接失败也不能单独证明 ESMC 没有足够信息。
4. 当前对照先保留原输出、loss 和采样规则；结构监督、多噪声训练和几何
   适配是后续按证据选择的候选，不同时启动方法矩阵。

正式训练前预声明样本、更新预算、学习率、验证时点、比较指标与失败门；
仅用 TRAIN 拟合桥接，不用 DEV 特征拟合变换或统计量。固定测试集继续封存。
不能把原生 ESM2、不同输入预处理与 ESMC 差异全部归因于 pLM：先做原生输入
复现以控制运行路径，再做条件接口比较。报告父模型预训练成本与新适配成本。
